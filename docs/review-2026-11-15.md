### Checked and safe

From the security report unless noted.

- Restore blocks path traversal (`src/maintenance.rs:164`).
- HLS file requests check the session id (hex) and segment names (`segNNNNN.ts`) (`src/handlers.rs:643`).
- People keys are limited to `[a-z0-9-]`.
- ffmpeg is always started with an argument list, never through a shell; the download concat list escapes quotes (`src/downloads.rs:322`). No command-injection point found.
- Password, relay and TOTP comparisons are constant-time; sign-in has a 400 ms delay and lockout per user and per IP (`src/handlers.rs:50-74`).
- The server's own `server.log` records the path only, not the query, so `?token=` is not logged there (security and web reports).
- Web report: the web app builds UI text with `h()` (text only); the three `innerHTML` uses hold fixed SVG or a server-built QR code.
- Ops report: nfo-reader does not load external XML entities; the CI logs contain no secrets; webhook posting to LAN addresses is admin-only and is the plugin's purpose, so not a finding.

## Before deploying to main

Every push to `main` deploys to the NAS. Do these, in this order where it matters:

1. Run `sudo chown -R 1026:100` on the config folder (for example `/volume1/docker/lichtspiel`). The container no longer runs as root (`cd9586b`), and the deploy stops at the `/config` check if the folder is not writable.
2. For hardware transcoding, add `--group-add <gid of /dev/dri/renderD128>` to `LICHTSPIEL_DOCKER_ARGS`, or the non-root user can't open the GPU.
3. Update Lichtspiel on the relay computer before the NAS. A new home server refuses a relay that can't prove the secret (`c4f405f`).
4. A rollback after this deploy signs everyone out: tokens are stored as hashes (`17af37a`) and an older version can't read them.
5. Third-party browser clients on other websites stop working: there is no `Access-Control-Allow-Origin` any more (`c4f405f`).
6. Symlinks that point outside the library folders are no longer played or scanned (`c4f405f`).
7. "Poster from URL" can't fetch LAN or localhost addresses any more (`c4f405f`).
8. Tailscale or CGNAT clients (100.64.0.0/10) must be added to the "home network" setting to be answered by discovery (`17af37a`).
9. Open the web app once after the deploy and check the browser console for CSP errors (blocked scripts or frames).

## Outside the code

Port 8484 is open to the internet over plain HTTP, so passwords and tokens cross the internet unencrypted. Put it behind the DSM reverse proxy with a Let's Encrypt certificate, or turn on HTTPS in Lichtspiel, and close the plain port in the router.

## Client connection problem of 2026-11-15

The app could not connect, and only showed one generic error. The cause was three things together: the server address was entered as `https://` while the server only speaks plain HTTP on that port; the app had no timeouts, so the TLS handshake hung instead of failing; and every failure ended in the same message, which did not say what went wrong.

Fixed in `0d48314`: a silent server gives up after 10 seconds (GET; 2 minutes for writes), errors say the cause in German, an `https://` address falls back to `http://` with a notice, server errors are shown in German, and IPv6 addresses get the default port. On the server side, `2c4141c` makes `https://` on the plain port fail at once instead of hanging.
